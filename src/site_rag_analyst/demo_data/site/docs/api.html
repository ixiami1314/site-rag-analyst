API reference (v2)

The Meridian Flow REST API lets your systems start flows, read documents and subscribe to events. The base URL is https://api.meridianflow.test/v2; all endpoints accept and return JSON.

Authentication

API requests authenticate with bearer tokens created in Personal Settings or, preferably, workspace-scoped service tokens. Tokens carry the role of their owner; service tokens can be scoped to a single flow. Rotate tokens any time — old tokens remain valid for 24 hours after rotation as a grace period.

Rate limits

The API allows 600 requests per minute per workspace, with a burst of 60. Responses include X-RateLimit-Remaining headers, and 429 replies carry a Retry-After header. Sustained limit overage is never billed — requests are simply throttled.

Pagination

List endpoints paginate with cursors: pass the cursor from next_page_cursor until it comes back null. Cursors are stable for 24 hours. Page size defaults to 50 and can be raised to 200.

Webhooks

Subscribe to flow events (run.started, step.waiting, run.completed, run.failed) per flow or workspace-wide. Each webhook has a signing secret; payloads are signed with HMAC-SHA256 in the X-Meridian-Signature header. Failed deliveries retry with exponential backoff for 24 hours — retry controls shipped in version 2.3.0.

Core endpoints

  • POST /v2/runs — start a flow run with input documents
  • GET /v2/runs/{id} — run status, step timeline and outputs
  • GET /v2/documents — list documents with cursor pagination
  • POST /v2/runs/{id}/approve — resolve an approval step

Errors

Errors are JSON with code, message and request_id. Rate limit errors return 429 with Retry-After; validation errors return 422 with a field-level details array. 5xx errors are safe to retry with backoff. Include request_id when contacting support — it resolves to the exact trace.

Idempotency

POST /v2/runs accepts an Idempotency-Key header. Replays within 24 hours return the original run instead of starting a duplicate — use this for retries after timeouts. Webhook deliveries are idempotent by delivery id.

SDKs

Official SDKs: Python (pip install meridianflow), TypeScript (npm @meridianflow/sdk), and a CLI (brew install meridianflow-cli). SDKs are generated from the OpenAPI schema, so every endpoint here is available with typed responses.

Versioning

v2 is the current major version; v1 sunset is scheduled for June 2027. Breaking changes ship behind new minor versions with a migration window of at least two quarters. Schema additions are never breaking — unknown fields should be ignored by clients.
